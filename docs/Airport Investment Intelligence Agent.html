The job

Help a fund pick where to build

The firm invests in airport modernization. It needs to know which airports a terminal or runway build will make most productive — and to ask in plain English.

  • "Which New England airports are strong expansion candidates?"
  • "Compare LA and Santa Ana congestion."
  • "% long-haul out of Anchorage?"
  • "Unmet demand at SFO — and why?"
The insight most candidates miss

Big & growing isn't enough — it must be choked

the differentiator

🚦 Choke

The airport is full — long delays or capped flights. If it still has room, there's nothing to fix.

📈 Demand

Traffic is growing, so new capacity gets used.

🏗️ Scale

Big enough to justify a major build.

A huge airport with spare room just absorbs growth. Choke is what turns a build into profit — so the whole score is built around it.

The scoring logic (deterministic, not the LLM)

One number: the Expansion Opportunity Score

EOS = ( Choke 45% + Demand 30% + Scale 25% ) × ( 0.60 + 0.40 × Choke )

Demand & Scale come straight from the data (growth · size). Choke = how jammed it is — delays + cancellations + runway use + an FAA-cap bonus, as a 0–100 score.

Choke is used twice: it adds points (the 45% pillar) and multiplies the whole score (the gate).

Where the numbers come from

4 public data sources — in plain words

Everything is pulled from open government & aviation data into one snapshot — so answers are fast and the same every time.

🗺️ OurAirports

Where each airport is, and how many runways it has → the map, and how full the runways run.

👥 FAA passenger data

How many people flew in 2024 vs 2023 → an airport's size and its growth.

⏱️ BTS flight records

Delays, cancellations, and how far each flight goes → how jammed it is, plus long-haul %.

🏛️ FAA capacity rules

Which airports the FAA legally caps flights at (JFK/LGA/DCA/EWR) → the strongest "no room" signal.

All public. Downloaded once and joined into data/airport_snapshot.parquet — reproducible and demo-safe.

The system prompt

The rules that make it trustworthy

The agent's instructions, in plain words — this is what turns a chatbot into an analyst you can trust.

▸ SYSTEM PROMPT — the agent's operating rules

🔒 Stay honest

  • Never state a number from memory — every figure comes from a tool.
  • No data? Say so. Don't guess or fake capability.
  • It ranks capacity need, not profit — no ROI, no investment advice.
  • Flag the soft spots — low confidence, scope, "proxy not forecast".

🎯 Reason like an analyst

  • Resolve fuzzy names first — "LA" → LAX before answering.
  • Apply the thesis — choke is required; explain which pillars drove a score.
  • Check "#1 / highest" claims before agreeing — verify, don't assume.
  • Lead with the answer, concise analyst voice, offer a follow-up.

Most of these are enforced in code too (a grounding guard, name resolver, superlative check) — so they hold even when the model slips.

Tradeoffs & what's next

Honest about the edges

  • Demand = one year of growth — noisy; a multi-year trend / FAA forecast is the first upgrade.
  • No gate/seat data exists publicly — capacity proxied by runways + slot-control + utilization.
  • Delays = 3 sampled months, domestic-only — understates international gateways.
  • Snapshot is CY2024 — refresh on a schedule for production.

All weights + the gate floor live in config.py — tunable, not buried.
