1The idea in one line

The business makes money by building physical capacity and earning fees + passenger revenue on the new traffic. That only pays off at a choke point — an airport that is full and turning flights away. A good target needs three things at once:

the differentiator

🚦 Choke

It's jammed — chronic delays, runways near 100% use, or the FAA legally caps flights. If it has room, no build is needed.

📈 Demand

Traffic is growing, so the new capacity will actually get used.

🏗️ Scale

Big enough that a hundreds-of-millions build is worth it.

Why most people get this wrong: the obvious move is to rank airports by size or growth. But a huge, fast-growing airport with spare room doesn't need a build — it just absorbs the growth. Choke is what makes capacity profitable, so we build the whole score around it.

2The score — how it works (in plain English)

Every airport gets one number from 0–100: the Expansion Opportunity Score (EOS). Higher = a better place to build. It blends the three ingredients, then multiplies by a choke gate.

EOS = ( Choke 45% + Demand 30% + Scale 25% ) × Choke-gate

Each ingredient is a national percentile (0–100) — how an airport ranks against every other. Percentiles are used because they're unit-free, robust to outliers, and easy to read.

The choke gate is the whole trick

gate = 0.60 + 0.40 × choke   The gate shrinks the score when an airport isn't jammed. So an airport can't ride scale + growth to the top — it needs a real bottleneck. The thesis is baked into the math, not left to the LLM.

Read it: a plain weighted sum would score Maui ~37 and float it up the list on its size. The gate drags it to 27 — correctly saying "growing tourism, but it isn't choked, so a build won't pay." That single design choice is what makes the ranking match the investment thesis.

Every score is fully decomposable — the agent shows each ingredient's percentile, weight and contribution, so it can explain a ranking instead of asserting it. Top 5 nationally today: CLT 88 · DFW 83 · PHX 82 · SAN 81 · DEN 81 — all big, choked hubs. ✔️ face-valid.

3Architecture & flow

Three clean layers. The LLM plans and explains; code decides every number; heavy analytics read a cached snapshot (fast, reproducible) while two live public APIs add freshness.

The heavy data sits in a data/airport_snapshot.parquet built once, offline, from the public sources — so the demo is fast and gives the same answer every time. The LLM sits behind one seam (llm.py), so Gemini and Claude are interchangeable.

What happens on one question

  • Understand & resolve — "LA" → resolve_airport → LAX (and it lists SNA/BUR siblings). Ambiguous names like "Portland" are disambiguated, not guessed.
  • Pick tools — the model chooses rank_airports, compare_airports, airport_report… and can call several at once.
  • Compute in code — the tool returns code-computed facts (never the model's memory).
  • Explain — the model turns the numbers into an analyst-style answer with the caveats that matter, and handles follow-ups (it remembers the conversation).

5Tools & logic

The agent has 9 typed tools. Each returns code-computed facts; the model only chooses which to call and how to phrase the result.

name/city → IATA code(s); disambiguates "LA", "Portland"
airport_report
full metric + EOS breakdown for one airport
rank_airports

live_traffic

live official domestic segments (BTS)

dataset scope, coverage, assumptions
The guardrail candidates miss: a structural grounding check. If the model ever writes a figure (a score, %, passenger count) without having called a data tool that turn, the loop refuses the answer and forces a tool call. Live APIs fail closed — an OpenSky outage returns "unavailable", never a made-up number. This is what makes an investment tool trustworthy.

6Where AI is used — and where it isn't

The split is deliberate: AI for language, code for numbers.

🤖 The LLM does

  • Understand the question & ambiguity
  • Choose tools + arguments, sequence steps
  • Explain reasoning & methodology
  • Carry the conversation (follow-ups)
  • Transcribe voice (Gemini)

🧮 Code decides

  • Every score, percentile & ranking
  • The choke gate & all weights
  • Passenger, delay, long-haul figures
  • Name resolution & region lookup
  • What counts as "grounded"

This satisfies "deterministic scoring, not only LLM output" and removes the failure mode that would sink an investment tool: hallucinated statistics.

7Honest by design — assumptions, uncertainty, scope

The one misread to avoid: EOS ranks where capacity is most needed / productive — a precondition for profit. It is NOT an ROI model (no construction cost, revenue, or airline fees). It's the shortlist for diligence, not the diligence. Ask it "most profitable?" and it says exactly that.

Assumptions

  • Long-haul ≥ 2,000 mi; "late" = departs > 15 min behind
  • Demand = 2024 vs 2023 passengers (one year — the weakest pillar, noisy on small bases)
  • Slot-control list curated from FAA Level-3 (JFK/LGA/DCA/EWR)

Scope & uncertainty

  • US commercial airports only
  • Delays mix weather/ATC with real choke → never used alone
  • "Unmet demand" is a directional proxy, not a forecast

8Simplicity & scope discipline

The brief said "prioritize clarity and reasoning over completeness or polish." So the effort went where it counts.

The graded core (read this)

  • scoring.py — the choke-gated KPI, ~pure functions
  • tools.py — 9 tools + the grounding guard
  • agent.py — the LLM loop + thesis prompt

One idea, cleanly expressed. If you read one file, read scoring.py.

Optional polish (on top)

  • Dark dashboard: map + live rankings
  • Floating chat with streaming replies
  • Voice input (the bonus)

Nice to have — but it's presentation over the same tools, not the substance.
